# Github PR 작성

> Github PR 작성 시 Claude가 따르는 절차와 멘트 규격
>
> 이 스킬은 규칙을 정의하지 않는다. 규칙은 아래 원본 문서에만 있으며, 스킬은 읽을 위치와 수행 순서만 안내한다.

---

## 0. 원본 문서

| 문서 | 읽을 섹션 | 용도 |
|---|---|---|
| `Docs/Claude/WorkflowRules.md` | `5. 업무 수행`, `9. PR` | 변경 파일 목록 기준, 생성 조건 |
| `Docs/Documentation/GithubPRRule.md` | 전체 (`1. Title` ~ `7. 특이사항`) | 섹션별 작성 규칙, 말머리 |
| `Docs/Template/PRTemplate.md` | 양식 코드블록 | PR 본문 양식 |
| `Docs/Documentation/GithubBranchRule.md` | `1. 기준 브랜치` | PR 대상 브랜치 |

- 각 단계에서 표기된 섹션만 읽는다.
- 원본 문서와 이 스킬의 내용이 다르면, 원본 문서를 따르고 사용자에게 차이를 보고한다.

---

## 1. 정보 수집

- 연결된 Issue 번호와 Label을 확인한다. 알 수 없으면 사용자에게 질문한다.
- 변경 파일 목록은 `WorkflowRules.md`의 `9. PR`에 따라 검수 보고에서 가져온다.
  - 검수 보고가 없는 경우(이전 세션 작업 등), 사용자에게 변경 파일 목록을 요청한다.
- 아래 **멘트 A** 로 변경 파일을 확인받는다.

**멘트 A : 변경 파일 확인**

```markdown
**PR 작성 정보 확인** : [브랜치명]

- 연결 Issue : [#번호 / 없음]
- 검수 보고 기준 변경 파일 :
  - 생성 : [경로]
  - 수정 : [경로]
  - 삭제 : [경로]
- Commit에 포함된 파일과 일치하나요? 다르면 알려주세요.
```

---

## 2. 초안 작성

- `PRTemplate.md`의 양식으로 본문을 작성한다.
- 각 섹션은 `GithubPRRule.md`의 해당 섹션 규칙에 따라 작성한다.
- 작성 대상의 코드 / 문서를 확인해야 하는 경우, 읽기만 하며 수정하지 않는다.

---

## 3. 생성 전 승인

- 승인 요청에는 아래 **멘트 B** 의 요약만 보여준다.
- 사용자가 전문을 요청하면 본문 전체를 보여준다.

**멘트 B : 생성 승인 요청**

```markdown
**PR 생성 확인**

| 항목 | 내용 |
|---|---|
| 제목 | [말머리] [제목] |
| 브랜치 | [작업 브랜치] → main |
| 연결 Issue | [Closes #번호 / 없음] |
| 작업 내용 | [항목 n개] |
| 사용자 확인 필요 | [체크하지 않은 확인 사항 항목] |

생성할까요? (전문 확인 시 "전문")
```

---

## 4. 생성

- `gh` CLI로 PR을 생성한다.
- 생성 후 PR 번호와 링크를 보고한다.
- 병합은 `WorkflowRules.md`의 `10. 병합, 브랜치 파기`를 따른다.

**멘트 C : 생성 완료**

```markdown
**PR 생성 완료** : #[번호] [제목]

- 링크 : [URL]
- 사용자 확인 필요 : [체크하지 않은 확인 사항 항목]

확인 사항 체크 후 병합을 진행해주세요.
```
