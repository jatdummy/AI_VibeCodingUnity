# Github Issue 등록

> Github Issue 등록 시 Claude가 따르는 절차와 멘트 규격
>
> 이 스킬은 규칙을 정의하지 않는다. 규칙은 아래 원본 문서에만 있으며, 스킬은 읽을 위치와 수행 순서만 안내한다.

---

## 0. 원본 문서

| 문서 | 읽을 섹션 | 용도 |
|---|---|---|
| `Docs/Claude/WorkflowRules.md` | `1. 업무 유형`, `2. Github Issue` | 권유 조건, 등록 후 행동 |
| `Docs/Documentation/Github Issue Rule.md` | 전체 (`1. Title` ~ `7. 기타`) | 섹션별 작성 규칙, Label |
| `Docs/Template/Issue Template.md` | 양식 코드블록 | 이슈 본문 양식 |

- 각 단계에서 표기된 섹션만 읽는다.
- 원본 문서와 이 스킬의 내용이 다르면, 원본 문서를 따르고 사용자에게 차이를 보고한다.

---

## 1. 이슈 등록 권유

- `WorkflowRules.md`의 `2. Github Issue`에 정의된 권유 조건에 해당하는지 확인한다.
- 해당되면 아래 **멘트 A** 로 권유하고, 사용자의 결정을 기다린다.
- 사용자가 직접 이슈 등록을 요청한 경우, 이 단계를 생략한다.

**멘트 A : 등록 권유**

```markdown
**Issue 등록 권유** : [권유 사유 (권유 조건 중 해당 항목)]

- 제안 제목 : [기능 단위 제목]
- 범위 : [한 줄 요약]

이슈로 등록할까요?
```

---

## 2. 정보 수집

- `Github Issue Rule.md`의 `2. 배경 / 목적`을 읽고, 해당 섹션에 기재할 내용을 사용자에게 질문한다.
  - 답변을 받지 못하면 이슈를 작성하지 않는다.
- 나머지 섹션은 `Github Issue Rule.md`의 각 섹션 규칙에 따라 Claude가 초안을 작성한다.
- 작성 대상의 코드 / 문서를 확인해야 하는 경우, 읽기만 하며 수정하지 않는다.

**멘트 B : 배경 / 목적 질문**

```markdown
**Issue 작성 정보 요청** : [제안 제목]

- 이 작업이 필요한 배경 / 목적을 알려주세요.
  - (예) [Claude가 추정한 배경 1줄]
```

---

## 3. 등록 전 승인

- `Issue Template.md`의 양식으로 본문을 완성하되, 승인 요청에는 아래 **멘트 C** 의 요약만 보여준다.
- 사용자가 전문을 요청하면 본문 전체를 보여준다.
- 사용자의 승인 없이 등록하지 않는다.

**멘트 C : 등록 승인 요청**

```markdown
**Issue 등록 확인**

| 항목 | 내용 |
|---|---|
| 제목 | [제목] |
| Label | [Label] |
| 목표 | [목표 (To-be) 요약 1~2줄] |
| 작업 파일 | [생성 n / 수정 n / 삭제 n] |
| DoD | [체크리스트 n개] |
| 특이사항 | [있음 : 요약 / 없음] |

등록할까요? (전문 확인 시 "전문")
```

---

## 4. 등록

- `gh` CLI로 등록한다.
  - Label이 저장소에 없으면 `Github Issue Rule.md`의 `7. 기타`에 따라 Label을 먼저 생성한다.
- 등록 후 이슈 번호와 링크를 보고한다.
- 이후 행동(착수명령 대기, Assignees 지정)은 `WorkflowRules.md`의 `2. Github Issue`를 따른다.

**멘트 D : 등록 완료**

```markdown
**Issue 등록 완료** : #[번호] [제목]

- 링크 : [URL]

착수명령을 주시면 브리핑을 진행합니다.
```
